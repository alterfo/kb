Deterministic Playback Manifest format (draft)

Purpose:
This is a working sketch of a lightweight, self-contained manifest format intended to capture everything needed to deterministically replay an inference session (or a set of requests) across model rollouts, runtime variants, and quantization changes. The goal is to make postmortems, regression triage, and model A/B comparisons reproducible without requiring full environment cloning.

Non-goals (for v1):
- Not attempting to capture private customer data; manifests should be able to reference redacted payloads or point to secure storage locations.
- Not a full provenance ledger; this is focused on deterministic playback for debugging/regression.

Design principles:
- Minimal: small manifest that references artifacts rather than embedding bulk blobs.
- Deterministic intent: include all inputs that can affect output (tokenizer, seed, model artifact id, runtime config, injected policies).
- Portable: JSON-compatible, human-readable, and easy to attach to support tickets or GitHub issues.
- Privacy-aware: fields that may contain PII must be flagged and optionally replaced with redaction pointers.

Top-level fields (v1):
- manifest_id: short id (UUID recommended)
- created_by: name/email of the authoring agent (person, system)
- created_at: ISO date
- source_context: freeform string describing the scenario (UI flow, API route)
- requests: ordered list of request descriptors (see below)
- environment: runtime/environment snapshot (hardware/host tags, region, container image)
- model_artifact: model id + exact artifact checksum (sha256) + quantization profile id
- tokenizer: tokenizer version id + checksum + tokenizer config (if nonstandard)
- runtime_flags: map-like list of runtime knobs that influence execution (e.g., use_kv_cache=false)
- deterministic_seeds: list of PRNG seeds used for sampling or other non-deterministic logic
- telemetry_refs: pointers to associated logs, traces, and metric snapshots
- privacy_policy: small token describing redaction level (none, partial, strict)
- signature: optional signed blob for integrity verification (OIDC/JWKS compatible)

Request descriptor (ordered list element):
- request_id: short id (monotonic in manifest)
- timestamp: ISO timestamp of original request
- api_route: e.g., \"/v1/generate\" or \"/v1/chat/completions\"
- client_sdk: client library and version (if applicable)
- raw_payload_ref: pointer to stored payload (S3/GCS/secure-store) OR inline (redacted) string
- input_checksums: list of checksum objects (tokenization checksum, raw text checksum)
- sampling_config: temperature/top_k/top_p/typical_p/seed (if used)
- pre_hooks: list of transformations (name@version + diff/checksum) applied by client or proxy
- post_hooks: list of response transformations (e.g., de-identification, markup)
- expected_response_signature: optional small fingerprint of the original response to enable quick divergence checks
- fallback_policy_trace: if fallback occurred during original call (e.g., switched to smaller model), record decisions and timestamps

Environment (examples):
- host_os: ubuntu-22.04
- runtime_image: redwood/runtime-infer:2025-10-21
- gpu: a100-80gb (or cpu)
- region: us-west-2
- concurrency_profile: \"single-req\" | \"batched\"

Telemetry references:
These are URIs (or internal artifact ids) pointing to:
- structured trace (jaeger/span id)
- token-level metrics (latency per token)
- server logs (filtered range)
- resource utilization snapshot (GPU memory thread dump)

Privacy notes:
- raw_payload_ref should be used in combination with privacy_policy. For strict privacy, manifest contains only a redaction pointer that trusted ops can use to fetch the unredacted artifact.
- tokenizer checksums avoid including raw text; a small mapping table may be included for debugging if permitted.

Repro playback flow (implementation notes):
1) Validate: check manifest signature (if present), model artifact checksum, tokenizer checksum. Bail if missing required artifacts.
2) Acquire artifacts: pull model variant + tokenizer. If quantization profile mismatch with available runtime, follow policy: either simulate (not ideal) or fail fast and record mismatch in report.
3) Materialize inputs: fetch raw_payload_ref (honoring privacy) and apply pre_hooks in order. Recompute tokenization checksum and assert equal to manifest's checksum.
4) Configure runtime: apply runtime_flags and sampling_config. Seed RNGs.
5) Execute: run request(s) single-threaded in deterministic mode (disable nondeterministic kernels where possible) and capture token logs + timings.
6) Compare: compute response fingerprint and compare with expected_response_signature. Record diffs at token, sentence, and semantic (embedding distance) levels.
7) Report: output an artifacts bundle (resulting tokens, metrics, delta report) and attach back to the manifest.
