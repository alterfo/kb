Cookie-domain rotation during canary causes pinned session eviction for long-poll streaming clients

Issue summary: After a targeted canary that adjusted cookie domain and SameSite attributes for cross-subdomain routing, a subset of long-poll streaming sessions from BrightChat saw their model version pin removed and traffic routed to the fallback model. Impact: ~6% of BrightChat tenant requests in us-east (long-poll streaming) returned responses from fallback variant (rwi-7b-compat) for durations up to 18 minutes. Customer impact: degraded generation quality and intermittent streaming disconnects for live agents.

Environment: production (us-east), Dedicated cluster for BrightChat (tenant id bc-091). Canary change: edge-proxy cookie domain normalization in PR https://github.com/redwood-inference/platform/pull/4872 rolled to 10% (cohort) starting 2026-03-12 03:10 UTC.

Steps to reproduce:
1) Start a long-poll streaming chat session using BrightChat tenant credentials (session cookie set to api.brightchat.com).
2) Observe router affinity header (x-tenant-session) and cookie domain in request/response.
3) Trigger a model request that is pinned to rwi-13b-v1 via tenant pin.
4) Monitor routing decisions in router logs and session-manager for pin refresh events.

Observed behavior: When the canary cohort hit an upstream edge with cookie-domain rewrite set to ".redwood.ai" (intended for drain handling across subdomains), the session cookie returned to the client with a different domain scope. For long-poll clients that reuse the original host-bound cookie, the session-manager validated the cookie as mismatched and treated the session as unauthenticated for pin reconciliation, causing the pinned routing key to be dropped and the request to be evaluated for fallback path. This only affected streams where the client reused the old host-scoped cookie and did not immediately refresh session metadata.

Logs / Traces: Relevant samples in trace-id list: trace: us-east-20260312-8a9b, us-east-20260312-8a9c; edge-proxy logs show Set-Cookie: session=...; Domain=.redwood.ai at 03:17:02 UTC. Router logs show pin_eviction_reason=COOKIE_DOMAIN_MISMATCH and decision=FALLBACK at same timestamps.

Workaround: For affected tenants, toggle canary off for edge cookie rewrite or instruct client to force a session refresh (POST /v1/sessions/refresh). Both steps reduced impact immediately.
