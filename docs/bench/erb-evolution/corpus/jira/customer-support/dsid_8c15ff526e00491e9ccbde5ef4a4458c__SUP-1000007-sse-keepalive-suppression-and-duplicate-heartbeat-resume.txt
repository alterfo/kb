Short-lived SSE disconnects during long-running telemetry streams cause truncated final block and duplicate heartbeat frames on resume

Issue summary: Customer (Nimbus Health) observed intermittent short TCP/TLS handoff events during long-lived SSE telemetry sessions. When those handoffs occurred the stream would resume but the final application-level 'end' chunk was missing and the client received one or more duplicated heartbeat frames. Impact: Several production streams for real-time device telemetry saw truncated final paragraphs and missing end-of-stream metadata. This caused Nimbus Health's post-processing job to treat sessions as incomplete and triggered follow-up alerts and duplicate downstream summaries. Observed frequency: ~3-4 occurrences/hour for a subset of sessions lasting >6 minutes. Reported first via support channel on 2026-03-10 04:12 UTC.
1) Start a long-running telemetry SSE session to /v1/streams/telemetry with keepalive enabled and session_id header set
2) Simulate an upstream idle probe from an edge load balancer (tcp RST after 30s idle) or trigger a client network change (cellular->wifi) during the stream
3) Allow client to reconnect using our resume protocol (last_seq parameter) and observe the final blocks emitted
4) Note occurrences where the terminal 'end' event does not arrive but heartbeat frames are duplicated and prefixed to resumed payload

Initial hypothesis: edge-proxy idle RST during a brief network hiccup left sse-gateway in a partially closed state, causing a race between keepalive emission and terminal chunk flush
Trace analysis: sequence gaps and duplicate heartbeat flag indicate gateway retransmitted heartbeat while serving-runtime was simultaneously finalizing the stream; ordering not guaranteed when upstream socket closed mid-flush
Reproducer: forcing a 30s idle RST from our internal apg-style probe reproduced missing end_event in canary under specific timing (client resume within 100-200ms of RST)
Client-side contribution: Nimbus client SDK retried immediately and attempted resume with last_seq causing gateway to interleave replayed heartbeat and resumed payload
Race condition in sse-gateway where in-flight terminal chunk flush and scheduled keepalive/heartbeat could be interleaved after a mid-flight upstream TCP RST, leading to the terminal 'end' event being dropped under tight resume timing
Rolled out inference-runtime PR 2147 which ensures atomic terminal event emission and orders heartbeat frames behind terminal flush. Applied a short backoff on client resume acceptance to tolerate in-flight socket tear-downs. Deployed to canary on 2026-03-11 and global rollout completed 2026-03-12.
PR 2147 modifies sse-gateway flush path to wait for terminal payload write to complete before accepting resume from the same session_id
