OpenAI-compat: resilient chunking + tool-signal proxy for Responses v9 (seed passthrough & metadata routing)

Motivation: Customers using the OpenAI Responses family expect stable streaming semantics, reliable tool/function call signal delivery, and preservation of determinism hints (seed/RNG) and user metadata when we bridge from our internal Responses v9-compatible runtime to the OpenAI API shape. This PR adds a resilience layer that: 1) performs backpressure-aware chunking and reassembly for streaming frames to avoid partial json/toolcall corruption on slow clients, 2) proxies a lightweight 'tool-signal' envelope so function/tool-calling boundaries are deterministic across retries and reconnections, and 3) forwards seed/determinism flags and a subset of user metadata transparently through the compatibility layer.

What this changes (summary): consistent chunk framing and reassembly on the server and client-facing bridge; explicit tool-signal envelope that annotates tool-call start/end + unique tool invocation id; passthrough of 'rng_seed' and 'deterministic' attributes from our Responses request model into the OpenAI-compatible response attributes; metadata routing (user-provided tags/trace id) added to response attributes and to audit logs so downstream services (console, evals) see the same identifiers.

Compatibility notes: We keep the OpenAI-compatible surface stable for existing callers. Default behavior is identical unless callers set determinism/seed or rely on streaming reconnects; in those cases the bridge guarantees idempotent framing (replay-safe chunk markers) and consistent toolcall reassembly. There are small opt-ins: the 'tool-signal' envelope is only applied when callers include a 'enable_tool_signal' flag (default true for our hosted API). For private deployments customers can opt-out via config.
