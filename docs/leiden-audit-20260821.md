# Аудит github.com/k8nstantin/go-leiden v0.1.0 (2026-08-21)

Предмет аудита: библиотека community detection на чистом Go, порт Rust-реализации
graspologic-native (Microsoft GraphRAG) алгоритмом Leiden (Traag, Waltman & van Eck, 2019).
Код сгенерирован AI-агентом (OpenPraxis), 0 человеческих коммитов — независимая проверка
обязательна перед включением (см. Task 11 плана).

## Вердикт

Аудит пройден с оговорками. Библиотека подключается как опциональная реализация
детектора сообществ за переключателем `KB_COMMUNITY_ALGO=leiden`; по умолчанию остаётся
Louvain (fail-open: при любой ошибке Leiden-прогона граф строится Louvain-детектором).

## Методика

1. Клонирован репозиторий (main, 0ed7d5e), изучены все исходники (17 файлов, ~4.3k строк).
2. Прогнаны `go test`, `go vet`, `go test -race`, fuzz-смоук (`FuzzLeiden`,
   `FuzzHierarchicalLeiden`) — все зелёные, крашей нет.
3. Эмпирическая проверка детерминизма: повторные прогоны с фиксированным seed на
   синтетических графах (karate, planted cliques, иерархическая фикстура kb).
4. Проверка валидационных тестов библиотеки: karate-club modularity попадает в
   опубликованный диапазон graspologic-native [0.38, 0.45].

## Что подтверждено

- Чистый Go, ноль внешних зависимостей, MIT, `go >= 1.22` (совместимо с go 1.26 kb).
- Корректная иерархическая модель: `HierarchicalLeiden` возвращает уровни от
  наимельчайших к самым крупным кластерам; каждый уровень — разбиение исходных узлов;
  `Final` — сошедшееся разбиение.
- Хорошая структура кода: CSR-граф (`CompactNetwork`), CPM-качество, фазы local move /
  refinement-from-singletons / aggregation с well-connectedness γ-гейтами, валидация входов
  сентинел-ошибками, детерминированный rng (seed → shuffle визитов + sampling).
- Результаты на фикстурах kb детерминированы для несимметричных графов: 30/30 прогонов
  идентичны на иерархической фикстуре (6 клик → 3 супер-группы), уровни 0/1/2.

## Оговорки (зафиксированы, не блокируют)

- Тай-брейк в local-move фазе идёт по порядку итерации Go-map: при точном равенстве
  ΔQ двух кластеров результат может различаться между прогонами с одним seed (авторы
  сами это документируют в validation-тестах). На симметричных фикстурах kb это
  наблюдалось (уровень-0 — 6 клик — стабилен всегда; крупные уровни варьируются).
  Митигация в kb: тесты используют несимметричные фикстуры и проверяют устойчивые
  свойства (уровень-0, покрытие, континуальность уровней), а не точные крупные разбиения.
- `context.Context` принимается, но не проверяется — отмены mid-run нет. Для масштаба kb
  (компоненты до ~сотен сущностей) приемлемо.
- AI-происхождение кода частично компенсировано встроенными валидационными тестами и
  нашими эмпирическими проверками; при росте корпуса стоит пересмотреть (аудит или замена).

## Интеграция в kb

- `internal/graph/community_leiden.go`: интерфейс `CommunityDetector`, реализации
  `LouvainDetector` (дефолт) и `LeidenDetector` (иерархический, с fallback на Louvain),
  фабрика `NewCommunityDetector` по значению `KB_COMMUNITY_ALGO`.
- `internal/graph/updater.go`: `GraphUpdater.WithCommunityDetector`; колонка `level`
  в `communities` заполняется для каждого уровня иерархии.
- `internal/config`: парсинг `KB_COMMUNITY_ALGO=louvain|leiden`, дефолт `louvain`.
